01 The problem

Agents write code that moves money.
Then they test it.

Payments, SMS, email, auth. Every integration an agent writes needs something to talk to, and every option today costs you something.

Real keys

Real consequences.

The agent can charge cards, text real people, burn credits and hit rate limits. One loop away from a bill.

Sandboxes

Accounts everywhere.

Sign-up and keys per provider, each set up differently. Many regional providers barely offer one.

Hand-written mocks

Lies that pass.

Canned JSON that breaks the moment the code does something new, or passes against an API that behaves nothing like the real one.

Remembers

Create it, then get it back.

Customers, payments, messages and issues persist. Refunds change what's left to refund. Deleted things are gone.

Behaves

Real shapes, real lifecycles.

Provider-style IDs, pagination and errors. Flows like queued → sent → delivered. Webhooks signed the way the provider signs them, so your verification code runs unchanged.

Breaks on purpose

Failure, on demand.

Declined cards, 3-D Secure, bounced email, unreachable phones. Force any of them from the dashboard or your agent.

03 Any API

Name it. Point at it.
Or let your agent read the docs.

Mock Anything reads an API's description and builds the twin itself: resources, IDs, state changes, pagination, errors and webhooks. Paths the spec misses still work.

  1. Built-in packnpx mockanything paystack

    Hand-tuned, with documented test values.

  3. Your specnpx mockanything api.yaml

    OpenAPI 3 or Swagger 2, file or URL. Inspect and override every guess.

06 Chaos

Find the failure
before your users do.

Turn on chaos and the twin misbehaves like a real provider on a bad day. Seeded, so the failure your agent found can be replayed exactly.

  • timeoutRequests hang until your client gives up.
  • 5xx500, 502 and 503 in the provider's error shape.
  • 429Rate limits with Retry-After.
  • slowResponses take one to four seconds.
  • dup-webhooksThe same event, delivered twice.
  • out-of-orderEvents arrive shuffled.
$ npx mockanything stripe --chaos --seed 42

07 Safe by default

Nothing real leaves your machine.

  • Local onlyListens on localhost. Webhooks go to localhost unless you allow a host.
  • No live keysLive keys are refused. Any placeholder works.
  • No real cardsReal-looking card numbers are refused. Use documented test values.
  • Plain test pagesCheckout and 3-D Secure pages are unbranded and say they aren't real.
  • No telemetryMock Anything doesn't phone home.

A twin is only as good as its facts. Packs cover each API's main flow, not every endpoint, and inferred twins make guesses you can see and override. Build fast against a twin; run final checks against the provider's sandbox. A fidelity report comparing a twin with the real sandbox is on the way.

08 Questions

FAQ

Is Mock Anything affiliated with Stripe, Twilio or the other providers?

No. Mock Anything is an independent, free, non-commercial project. Provider names are used only to say which API a twin is compatible with. Twins are built from public API facts, not from any provider's code or documentation text.

Do I need an account or API key?

No. Any placeholder key works, for example sk_test_mockanything. Live keys are refused.

Does anything I send leave my machine?

No. The twin runs locally and answers from memory. The only outbound traffic is the webhooks you point at your own app, and fetching an API description when you ask for one by name or URL.

Which APIs work?

Anything with an OpenAPI or Swagger description, more than 2,500 APIs by name from the public APIs.guru directory, the built-in packs, and APIs your agent describes from their documentation.

Can I use it in CI?

Yes. Start a twin before your tests and point your SDK's base URL at it. Use --seed to make chaos runs repeatable.

How do I add a provider?

Packs are plain YAML. The contributing guide in the repository explains the rules: facts only, no branding, and a test with the official SDK.
