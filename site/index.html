Nothing real leaves your machine.

  • Local only. Listens on localhost. Webhooks go to localhost unless you allow a host.
  • No live keys. Live keys are refused. Any placeholder works.
  • No real cards. Real-looking card numbers are refused.
  • Plain test pages. Unbranded, and they say they are not real.
  • No telemetry. Mock Anything does not phone home.
  • Measured, not claimed. mockanything verify compares a twin with the provider's real sandbox, using your own test key, and scores the match.

Questions.

Is Mock Anything affiliated with Stripe, Twilio or the other providers?

No. Mock Anything is an independent, free, non-commercial project. Provider names are used only to say which API a twin is compatible with. Twins are built from public API facts, not from any provider's code or documentation text.

Do I need an account or API key?

No. Any placeholder key works, for example sk_test_mockanything. Live keys are refused.

Does anything I send leave my machine?

No. The twin runs locally and answers from memory. The only outbound traffic is the webhooks you point at your own app, fetching an API description when you ask for one by name or URL, and the sandbox calls verify makes when you run it with your own test key.

Which APIs work?

Anything with an OpenAPI or Swagger description, the 2,529 APIs listed by name in the public APIs.guru directory, the built-in packs, HAR recordings of your own traffic, and APIs your agent describes from their documentation.

How close is a twin to the real API?

Run npx mockanything verify stripe --key sk_test_…. It makes the same calls to the twin and to the provider's sandbox and compares status codes, fields, types, id formats and error codes. Live keys are refused, and the report holds field names, never your data.

Does a twin remember data after a restart?

With --persist, yes. Objects, ids, the test clock and the webhook secret are saved to a file only you can read.

Can I use it in CI?

Yes. Start a twin before your tests and point your SDK's base URL at it. Use --seed to make chaos runs repeatable.

How do I add a provider?

Packs are plain YAML. The contributing guide in the repository explains the rules: facts only, no branding, and a test with the official SDK.
